## 关键决策

- 不新增 MCP tool：批量 = 服务端对同一批 id 循环调用既有 `issue_move` / `issue_delete`，
  失败原因与状态枚举校验仍在 MCP 内，tools 保持 7 个。
- 批量移动按勾选顺序追加到目标列尾部，沿用 `afterId` 语义，不引入新排序参数。
- 移入「失败」列复用单卡拖拽的同一套原因闸门；批量删除复用同一个二次确认弹窗（靠 `ids` 是否数组区分）。
- 清空筛选 / 重新拉取时清理失效勾选，避免误伤被筛掉或已被别处删除的卡片。

## 踩到的坑

- Express 里 `/api/issues/batch/move` 注册在 `/api/issues/:id/move` 之后时，`batch` 会被 `:id`
  匹配，批量请求一律返回 400「非法的任务 ID」。教训：**带字面量段的路由要排在通配段之前**。
