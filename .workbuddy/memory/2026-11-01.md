## 第二轮小步迭代（自动化任务）

从 OPTIMIZATION.md 待办里挑了 P3 乐观并发控制 + P3 触屏拖拽，两个独立 commit。

### 1. 乐观并发控制（3576083）

- `issues` 加 `version INT UNSIGNED DEFAULT 1`；schema.sql 里用 `information_schema` 判断 +
  `PREPARE/EXECUTE` 做幂等补列（MySQL 没有 ADD COLUMN IF NOT EXISTS），历史库自动升级。
- `issue_update` / `issue_move` 新增可选 `expectedVersion`，不一致时**返回 conflict 结构而非抛异常**，
  `server/index.js` 统一翻译成 409。校验仍在 MCP tool 内（铁律 4），HTTP 层只做状态码翻译。
- **关键取舍**：落位重排循环刻意不动 version —— 否则拖一次会让整列的乐观锁集体失效；
  只有真正被移动的那张卡 +1。
- 前端：编辑（modals）与拖拽（dnd）各自带上 `issue.version`；冲突时先 `onChanged()` 拉最新再报错。
- `api.js` 的 `request()` 抛错时挂上 `status`，供 409 与其它失败区分。

### 2. 触屏拖拽（722610a）

- `dnd.js` 内按 `pointerType` 分流：鼠标继续原生 HTML5 DnD，触屏 / 触控笔走 Pointer Events，
  两条路径最终都汇到 `performMove`，落位逻辑不写两份。
- 长按 220ms 激活，激活前位移 > 8px 判为滚动；边缘 64px 内自动横向滚动；
  拖拽期间给 board 加 `touch-dragging` 关掉 `scroll-snap-type`（会跟自动滚动打架）。
- **环境兜底**：Node / jsdom 下 `requestAnimationFrame`、`elementFromPoint`、`scrollBy` 全部缺失，
  已分别退回 `setTimeout`、列矩形命中、`scrollLeft +=`。
- UI 冒烟第 13 组用 `new Event('pointerdown')` + `Object.assign` 伪造 pointerType/clientX 来驱动，
  坐标取 0 才能命中（jsdom 里所有 rect 都是 0，几何兜底只认 x === 0）。
